## 1. 项目定位

项目标题：**Can AI Trade Alone? An Empirical Evaluation of an AI-Assisted Quantitative Trading Platform and Human Oversight**。

四人小组从零构建 AI 辅助量化交易平台。当前工作重点是实现可运行的平台，并为后续研究 AI 交易表现、局限性和人类监督价值保留实验能力。

平台是实验载体，AI Agent 是技术核心。不得预设 AI 优于传统策略，或人类监督必然改善结果；结论必须由实验支持。

## 2. 已确认的方向

- 使用 AI Agent 参与信息分析和交易决策，不将项目简化为普通股价预测模型或聊天界面。
- 支持历史回测，并为后续 paper trading（实时模拟交易）保留扩展空间。
- 核心实验支持 AI-only 与 AI + Human Oversight 的比较。
- 保存决策、交易及人工干预记录，使结果可以检查和分析。
- 分阶段实现，边开发边调整；不要求一次完成所有讨论过的功能。
- 以接入 LLM 的 Agent 为核心，通过可插拔专家策略卡片切换交易风格、提供顾问意见或组织多专家协作。
- 交易风格仅通过主交易 LLM 的系统提示词影响决策，不叠加风格化来源／因子加权机制；程序硬风控与模拟执行继续独立负责约束，具体见第 13 节。

## 4. 第一版范围与完成标准

按以下顺序形成可运行的闭环：

1. 导入行情，运行简单基准策略，完成订单、持仓、现金与资产曲线计算。
2. 接入一个 AI Agent，支持工具调用、结构化交易建议及决策记录。
3. 增加批准、修改、拒绝交易的人工审核功能。
4. 在相同实验设置下比较 AI-only、人机协同及基准结果。

第一版应能从网页创建并运行一段历史实验，查看逐笔交易及其依据，进行人工审核，并展示收益、波动率、最大回撤及基准比较。Sharpe 等指标应说明计算口径。

专家卡片按第 10 节分阶段实现。新闻与财报分析、市场状态分析、建议趋同研究、真人独立交易及实时模拟交易，均作为后续候选扩展，不自动计入第一版验收。

2026-11-10 四模式设计讨论已确认保留第一组量化基准，采用可追溯的开源量化策略实现。该组按确定性规则生成建议，记录上游版本、许可证、参数与适配改动，并使用 Lab 统一的数据可得性、费用、仓位限制和模拟成交规则。具体策略根据源码核查与接入验证选定。

## 5. Agent 与交易执行边界

- Agent 读取授权数据、调用工具、提出交易建议，不直接修改账户账本或绕过执行模块。
- 建议采用结构化格式，包含标的、动作、目标仓位或数量、依据、风险与所用信息引用。
- 程序负责订单校验、现金与仓位限制、成交、费用及资产核算。
- 无效输出、缺失数据、模型超时和调用失败必须记录；不得编造建议或成交来掩盖失败。
- 记录模型调用次数、耗时及可获得的费用信息；实验支持预算限制与中断恢复。

## 6. 数据与回测约束

- 每个决策只能使用当时已可获得的信息，区分事件时间、信息发布时间、决策时间和成交时间。
- 不得使用未来价格或尚未公布的财务数据生成过去的决策；明确决策后何时、按什么规则成交。
- 明确手续费、滑点、分红、拆股及价格复权处理，避免重复计入收益。
- 数据缺失、股票池选择及退市样本处理应有记录，披露由此产生的偏差。
- 保存数据快照或可定位的数据版本、实验配置、模型标识、提示词及实际输出。
- 现成大模型可能知道历史结果；时间截断不等于彻底消除知识泄漏，报告中必须说明这一限制。
- 调参阶段与最终评估阶段分开，不能反复查看测试结果后仍宣称其为未见数据。
- 演示、合成或占位数据必须明确标注，不得作为真实交易效果或研究证据。

## 7. 人类监督与对照实验

- 支持预先配置审核方式，例如全部审核或按条件触发审核。
- 保存 AI 原始建议、人工批准／修改／拒绝、原因、时间和最终订单。
- 历史审核只展示当时可用的信息；若参与者已知后续行情，应记录实验局限。
- 各组采用可比的起始资金、数据、交易成本及交易约束，并记录实际差异。
- 比较监督机制时，优先复用同一批原始 AI 建议；若干预改变后续持仓和决策路径，应保留完整轨迹并说明。
- 同时观察收益、风险、人工工作量及介入结果，不只比较最终收益。
- 2026-11-10 的旧加权人机协同模式同时支持调整信息融合权重与逐笔批准、修改、拒绝交易。两类历史操作分别保留审计；调权按第 11 节处理。2026-11-23 确认的风格 LLM 路径遵循第 13 节，不沿用调权作为风格控制方式，逐笔审核机制继续保留。

## 8. 开发与协作约束

- 先完成端到端闭环，再增加复杂策略和界面装饰；保持模块职责清晰，避免过早微服务化。
- 数据、Agent、执行、评估和界面之间通过明确接口协作。
- 资金核算、成交时序、风险约束和实验隔离应有针对性的自动化测试；界面交付前检查主要使用流程。
- 不将 API 密钥、账户凭据或私人数据提交到代码仓库；配置通过环境变量管理。
- 默认仅进行回测和模拟交易。真实资金、实盘下单及连接真实交易权限不在当前范围内。
- 不将建议、计划或未测试功能写成已完成；交付时说明完成内容、验证结果和未解决问题。
- 公开网络研究仅在原生 GPT/OpenAI 搜索实际可用时使用；不可用时明确说明，不擅自改用 MCP 搜索或浏览器搜索。

## 10. 专家策略卡片

### 产品行为

- 用户可将卡片加入交易实验，并选择“交易策略”或“顾问”角色，也可启用多个专家。
- 交易策略模式：卡片的风格内容按第 13 节编入主交易 LLM 的系统提示词，配置其目标、分析方法与决策原则，由该 LLM 形成订单建议。
- 顾问模式：卡片提供独立意见、风险提示或异议，由交易 Agent 综合判断，不直接下单。
- 多专家模式：各专家先独立输出，再由明确的协调规则或协调 Agent 汇总；最终只生成一份订单计划，避免重复下单。
- 同一底层 LLM 可承担多个专家角色；卡片不要求独立训练模型，也不因数量增加自动意味着有效分散风险。

### 卡片内容与能力边界

- 至少记录卡片 ID、版本、名称、策略目标、适用资产与周期、所需数据、可用工具、分析规则、风险约束和输出格式。
- 区分提示词指导的偏好与程序执行的硬约束；硬约束须由系统校验，不能仅依赖模型遵守。
- 缺少必要数据时，显示不可用原因或明确限制后的运行方式，不虚构估值、财报、新闻等信息。
- 以真实投资者命名的卡片须说明是基于公开理念的模拟，并记录可用来源；不得宣称复现其真实决策或获得本人认可。
- 卡片记录可观察的决策依据和数据引用，不将模型自述等同于对内部推理过程的证明。

### 动态切换与实验记录

- 支持随时提出启用、停用或切换请求；在明确的下一决策边界生效，不修改已完成的历史决策。
- 明确处理待审核建议和未成交订单，防止旧建议在切换后被误执行。
- 保存生效时间、角色、卡片版本、参与专家、汇总规则、各方意见和最终决策。
- 确证性实验固定配置；交互探索中的切换应标为配置变更，不与固定策略结果混称为同一实验条件。
- 首先完成单专家交易和单顾问模式，再增加多专家协作。交易风格的唯一入口遵循第 13 节；第 11 节仅保留旧加权机制的兼容／独立对照规则，投票、否决权限及讨论轮数仍待具体设计。

## 11. 历史机制：用户可调的信息融合权重

本节记录 2026-11-10 的产品设计决定及四模式初版接入，保留供既有实验兼容与显式独立对照。2026-11-23 的第 13 节决定优先；不得将本节的来源加权机制叠加到风格 LLM 路径。旧四模式采用独立来源评分和程序融合，原有专家团队实验沿用其交易员、顾问和协调者链路。

- 行情、新闻和财务 Agent 在独立上下文中提供统一口径的评分、证据及缺失说明，程序使用用户配置的权重汇总。
- 用户可在创建实验时配置各信息模块的融合权重。每项范围为 0% 至 100%，合计必须为 100%。初版多源与人机模板的工程初始值为 50% / 30% / 20%，可在创建时修改并保存。正式研究前须独立确定和冻结参数。
- 界面提供滑块与数值输入，显示当前总和、各模块得分、加权贡献及综合分。保存前校验范围、有限数值与总和。
- 运行中允许提出调权请求，在下一次新决策开始时生效。正在生成或等待审核的建议继续使用其原有权重版本。
- 每次建议保存实际生效的权重快照。调权记录包含原权重、新权重、提出时间、生效时间及操作者，已保存的历史评分与建议保留当时结果。
- 运行中调权作为一种人类干预单独统计。确证性比较固定权重配置，允许调权的探索实验记录全部变更，并在报告中披露。
- 模块证据缺失或过期时，显示其可用状态并执行预先确定的缺失处理规则。任何权重重分配都须显式显示并记录。
- 综合分用于产生交易候选，后续仓位计算和订单仍经过现金、集中度、敞口、换手及执行条件检查。

## 12. 历史实现：四模式接入初版

本节描述已有实现，不代表已经迁移到第 13 节的新规则。后续风格交易路径的开发与验收以第 13 节为准，历史实验保持原配置和原解释。

- 开源量化模板使用固定 bt 源码组件，提供 SMA50 趋势选股与一次性等权持有，输出交给 Lab 的统一执行器。SMA 窗口按输入频率计 50 个有效完整观察，适配差异与 MIT 许可保存在 vendor 说明中。
- 行情模板固定行情权重 100%，多源模板和人机模板分别配置行情、新闻、财务权重。分析角色以独立上下文顺序调用，保存真实输入、引用、评分、可得时间与提示版本。
- 评分采用统一的证据方向强度口径，范围为 -1 至 +1，零表示有依据的平衡。缺失信息使用 null 和不可用原因。程序按权重汇总有效来源。
- 初始进入阈值为 +0.25，退出阈值为 -0.25，观察窗口为 5 个未来完整 bar，均可配置并冻结。达到进入门槛的候选在可用风险预算内等权配置，中性和缺失来源的标的保留实际股数。人工修改提交完整目标仓位。
- 第一至第三模板自动排队执行，第四模板逐笔审核并支持调权。自动多源模板通过复制配置创建独立人机实验，运行中调权请求由人机模板接受。
- 分析历史按照模拟可得时间展示，调权请求总数、已生效次数、待生效数和交易审核数分别保存并导出。
- 演示模式显式标注确定性模拟，新闻和财务演示分数来自明确的合成证据字段。真实 LLM 使用可配置兼容接口，真实模型表现和真实采集器需要独立连接验证。
- 接口合同及验收记录分别见 `docs/FOUR_MODE_CONTRACT.md` 与 `docs/FOUR_MODE_ACCEPTANCE.md`。

## 13. 交易风格唯一通过主交易 LLM 的系统提示词生效

**用户于 2026-11-23 明确确认。本节是正式开发规则，优先于此前关于风格加权、程序融合和多阶段风格注入的设计。变更本规则须由用户明确决定。**

- 决策链路固定为：**统一分析证据 → 唯一带风格系统提示词的主交易 LLM → 程序风控 → 人工审核（如启用）→ 模拟执行**。主交易 LLM 负责综合证据并提出买入、卖出、等待及目标仓位建议。
- 卡片定义目标、证据解释偏好、行动／等待条件、退出原则和不确定性处理，并编入实际发送给主交易 LLM 的 `system` 消息。结构化卡片字段可以用于生成该系统提示词；仅展示卡片或只把风格放在普通输入文本中不算完成接入。
- 行情、新闻、财务等分析员按共享协议提供事实、正反证据、引用、可得时点和缺失说明；切换交易风格不改变它们的分析提示词，不把同一风格提前注入评分。
- 该路径不得再通过风格化来源／因子权重、加权综合分的买卖阈值或额外的方向评分重算交易。来源评分如保留，仅作证据说明；不得变成第二个风格控制器。模型生成的目标仓位比例属于交易输出，不属于本条禁止的来源加权。
- 最终交易建议必须由上述带风格系统提示词的主交易 LLM 生成。若复用已有协调者作为最终决策节点，应将它作为唯一的风格注入节点，避免上游交易员与下游协调者重复注入，或由不带该卡片的协调者重新自由改写风格决定。
- 程序继续强制检查现金、单股仓位、总敞口、集中度、换手、数据可得性、订单有效性及成交时序。硬限制与风格偏好分开；风格对照实验共用同一组硬限制。风控反馈修订沿用同一主交易角色及同一提示词版本，不添加另一套风格或来源权重；人工审核另存干预，不覆盖原始建议。
- 每次决策保存卡片 ID／版本、实际生效的完整系统提示词快照及版本或哈希、模型标识、输入证据和原始输出。卡片切换只在下一新决策边界生效，保留历史建议和人工操作。
- 确定性量化基准与历史加权实验可作为单独、明确标识的路径保留；它们不表示实现了此风格 LLM 规则，也不得静默用作模型失败时的替代结果。保留旧配置、权重轨迹及报告，不追溯改写。
