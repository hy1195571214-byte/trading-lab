## 视觉基准

**最终确认（2026-10-26）：采用最早的黑灰底、黄绿色强调与黑白像素工牌方案。该方案是后续所有组件、页面和前端实现的视觉依据。A／B／C 及其 V2 仅保留为未采用的配色探索，不作为实现基准。**

- 全局近黑 `#0C0D0C`，卡片炭灰 `#171917`，控件石墨灰 `#222522`。
- 主文字 `#F3F5EF`，次文字 `#ABB3A9`；黄绿 `#D6EE3E` 用于主操作、选中态与资产曲线。
- 盈亏和风险状态同时使用文字、符号及颜色，不只依赖红绿。
- 专家采用挂绳工牌、姓名栏、黑白像素头像、角色、启用状态与版本信息。
- 桌面基准 1440px；长页面垂直滚动。小于 1200px 时图表与审核面板纵向排列；移动端交易不在第一版范围内。
- 字体优先 Geist；本机不可用时使用 Inter，并在生成记录中注明。
- 所有展示数字均为演示，不构成实证结果。

## 信息架构

| 区域 | 页面 | 核心入口与去向 |
| --- | --- | --- |
| 工作区 | 总览、交易工作台、持仓与订单 | 继续运行、审核建议、查看订单 |
| 实验 | 实验列表、三步创建向导、完成与失败状态 | 配置数据 → 专家团队 → 风控与监督 → 启动 |
| 专家 | 专家库、策略详情、自定义卡片 | 查看方法与数据需求、添加交易员或顾问 |
| 审核 | 待办队列、决策证据、批准／修改／拒绝 | 审核结果进入订单及审计记录 |
| 评估 | 报告、实验对比、导出 | 检查可比性、观察收益风险与人工成本 |
| 支撑 | 数据中心、模型设置、活动记录 | 导入并校验数据、配置 LLM、追踪每次事件 |

## 三条主要用户路径

1. 创建实验：总览 → 实验列表 → 市场与数据 → 专家团队 → 风控与审核 → 交易工作台。
2. 人工监督：工作台或审核队列 → 决策证据 → 批准／修改／拒绝 → 结果确认 → 订单／活动记录。
3. 专家组合：专家库 → 详情 → 分配角色 → 下次决策生效 → 工作台查看意见与汇总结果。

## 关键操作规则

### 专家卡片

- 明确区分交易员与顾问。顾问不直接下单，系统最终只形成一份订单计划。
- 展示名称、版本、策略目标、适用周期、必要数据及风险偏好。
- 添加、移除、启停与角色调整在下一决策边界生效。
- 若有待审核建议，用户需明确选择保留当前团队完成审核，或废弃尚未执行的建议并重新分析。
- 缺少必要数据时阻止激活并给出补充数据／换策略入口。
- 自定义卡片先保存版本，再进入实验；测试输出应标注样例或实际调用来源。

### 历史回放与运行

- 时间轴仅显示当前回放时点已可见的信息。
- 启动前检查数据、资金、模型连接及预算；冻结实验配置和输入版本。
- 暂停停止新的决策和提交；保留现有持仓及记录。
- 步进进入下一个决策时点；如需审核则暂停等待用户。
- 运行中更换监督模式，创建新的实验分支，不覆盖旧配置。
- 模型失败、无效输出和预算耗尽均暂停，不虚构决策。

### 审核与执行

- 审核页同时展示原始建议、持仓影响、专家分歧及证据来源。
- 修改和拒绝需填写原因；同时保留原始建议与人工操作。
- 超过仓位、资金等硬限制时禁用提交，提示具体限制及修正方式。
- 批准表示进入待执行状态，不代表已经成交；仍按约定时点和费用规则执行。
- 拒绝不会自动卖出现有持仓，也不会创建替代订单。

### 报告、数据与设置

- 对比前检查日期、资产、资金与成本；差异需披露。
- 报告包含收益风险、费用、人工介入次数与时间、配置版本及局限。
- 数据导入产生新版本，不替换运行中实验的历史快照。
- 密钥始终遮挡，不出现在日志、导出或原型演示中。
- 设置更新默认只影响新实验，修改已有实验需显式分支。

## 组件与状态

- 按钮：主操作、次操作、弱操作、危险操作、悬停、键盘焦点、禁用、加载。
- 输入框：默认、焦点、校验错误、禁用；配标签与辅助文案。
- 标记：中性、激活、成功、警告、失败。
- 选择：开关、复选、角色选择、筛选、日期与时间回放控件。
- 业务组件：指标卡、资产曲线、专家工牌、审核面板、数据表格、证据列表、审计时间线。
- 通用状态：空白引导、加载、连接成功、数据阻塞、模型失败、操作确认、导出完成。

## 原型边界

Figma 用于检验页面层次、点击路径及代表性的状态转换。表单自由输入、上传文件、真实 LLM 调用、实际回测及报告文件生成属于后续平台实现，不应将原型确认画面当成真实执行结果。
