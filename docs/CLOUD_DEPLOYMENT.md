# Public cloud deployment

## Data access without waiting for the compute instance — 2026-11-24

The user chose to move ordinary page reads and saves off the sleeping instance while retaining Render for backtest computation. Cloudflare Workers now access the **same existing Neon PostgreSQL database over HTTPS**, using `@neondatabase/serverless`. There is one authoritative business database; no localStorage-only persistence, replica synchronization or periodic keep-alive is introduced. No paid plan, new database or new hosting service is required.

The edge handles public auth status, health, expert cards, dataset metadata, experiment lists and saved reports, reviews, activity, model settings, encrypted market credentials, harness metadata, JSON exports, and small date-only CSV imports up to 256 KiB. Large/timestamped imports, evidence validation, market replay aggregation, comparison/CSV report calculation, live collection, risk/review actions, experiment creation and actual execution stay on the Python compute service. Those computation/validation requests can still incur its first-start delay. An explicit `?live=1` on running-experiment polls requests the live compute process; ordinary saved-data reads do not. This is active-job monitoring, not a scheduled always-on workaround.

`edge_read_models` contains derived results generated by the original Python engine. Each experiment mutation/checkpoint writes its lightweight view in the **same transaction**. Completed report responses and settled background runs enrich it with the existing benchmark calculation. The edge checks a row-version token against current config/state/status/name and refuses an absent/stale view instead of silently showing old results or waking the compute instance. Database audit events are joined at read time. Pending benchmark calculations are labelled and their old curve is not plotted as current. Metrics, execution, point-in-time gates and immutable experiment snapshots retain the original engine.

Worker bindings:

- Secrets `DATABASE_URL` and `TRADING_LAB_ENCRYPTION_KEY` are set through the provider's secret interface, never static assets. The encryption key matches the existing backend so saved Fernet credentials remain usable; plaintext credentials are never returned.
- `EDGE_DATA_ENABLED="true"` and `EDGE_PUBLIC_WORKSPACE="true"` enable the new path only for the existing intentionally public shared workspace. Do not enable the public flag for a password-protected workspace. Private mode continues through the existing signed-session backend.
- `EDGE_SOURCE_REVISION` is a non-secret publication marker; origin URL/token remain necessary for compute routing.
- `TRADING_LAB_EDGE_READ_MODELS` defaults on with PostgreSQL and off for local SQLite. Local/portable launch behavior remains available.

The migration preserves the three original datasets, expert archive memberships, six existing experiment IDs, history and credential ciphertext. A private pre-migration snapshot and per-table checksums are kept under ignored `work/storage-migration/`; they must not be published. Derived-table preparation does not run process-restart recovery against the live service. Exact content comparison covers 24 read routes. Further runtime/latency acceptance is recorded separately; do not infer it from a build alone.

Rollback order: disable `EDGE_DATA_ENABLED` in the Worker first, then restore a backend revision if necessary. All routes then use the original gateway and the same database. No database restore or business-row replacement is needed. Keep the original encryption key; new derived tables may remain unused. Never serve a stale read model as a rollback shortcut.

Use only Free plans, no payment upgrade, paid disk, paid database, always-on workaround or purchased domain. ## Source and build

`Dockerfile` runs the existing Python engine in one Uvicorn worker. Keep one backend instance because the current experiment task locks are per process. `render.yaml` specifies `plan: free` and no paid disk/database. Docker copies only backend application source; local SQLite, private keys, uploaded datasets, logs and acceptance records are excluded.

Frontend: `npm --prefix frontend ci && npm --prefix frontend run build`.
Gateway: `npm --prefix cloudflare ci`, `node --test cloudflare/worker.test.mjs`, then `./scripts/cloudflare.sh deploy --dry-run` before publication. This wrapper keeps Wrangler auth/logs in ignored `work/` paths and disables optional CLI telemetry. Cloudflare config is `cloudflare/wrangler.jsonc`; static assets come from `frontend/dist`.

## Required runtime configuration

Backend environment (never commit values):

| Name | Purpose |
| --- | --- |
| `TRADING_LAB_ENV` | `production` enables required-config checks and Secure cookies |
| `DATABASE_URL` | Neon PostgreSQL connection string; require TLS (`sslmode=require`) |
| `TRADING_LAB_PUBLIC_WORKSPACE` | Set to `true` for the user-requested password-free public workspace; default application behavior remains private |
| `TRADING_LAB_WORKSPACE_PASSWORD` | Required only with password access enabled; shared workspace password, at least 12 characters |
| `TRADING_LAB_SESSION_SECRET` | Independent random signing secret, at least 32 bytes |
| `TRADING_LAB_ORIGIN_TOKEN` | Independent random origin secret, at least 32 bytes; must match Worker `ORIGIN_TOKEN` |
| `TRADING_LAB_ENCRYPTION_KEY` | Fernet key; required to preserve encrypted LLM keys across restarts |

Cloudflare Worker runtime:
- `ORIGIN_URL`: HTTPS Render service origin, with no path, credentials, query or fragment.
- `ORIGIN_TOKEN`: secret matching backend `TRADING_LAB_ORIGIN_TOKEN`; set with Wrangler secret input, never a tracked configuration value.

With `TRADING_LAB_PUBLIC_WORKSPACE=true`, `/api/auth/status` returns `auth_required: false` and the browser enters directly. Anyone with the public link can view and operate the shared workspace. In password mode, the browser authenticates to `/api/auth/login` using a signed HttpOnly/Secure/SameSite=Lax cookie. Direct backend business calls require the internal gateway token in both modes. `/api/health` remains a minimal public health check. This is one shared workspace, not independent user accounts; do not describe it as per-user data isolation.

No local SQLite, API key, existing private data or personal files are automatically migrated. Seed synthetic data only. The production model endpoint is unconfigured until the owner chooses one. A model provider may charge separately; deployment itself must not issue paid LLM calls.
