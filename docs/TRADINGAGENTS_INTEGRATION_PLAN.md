# TradingAgents 接入计划

日期：2026-11-08。状态：待实施的技术方案，不代表已安装、已接入、已完成真实模型验证。

## 1. 目标与选择

将 TradingAgents 作为 Trading Lab 的可选决策后端。保留现有实验管理、专家卡片、人工审核、风控、模拟成交、账户账本和报告。所有策略通过相同执行规则接受评估。

首期只接入 TradingAgents；沿用它依赖的 LangGraph，不同时迁移整个应用的工作流。不同时安装 AI Hedge Fund、Qlib 或 Backtrader。AI Hedge Fund 的专家定义可作后续设计参考，移植代码时另行记录来源和许可证。

遵循 PROJECT_CONSTRAINTS、UI_FUNCTIONAL_SPEC、IMPLEMENTATION_CONTRACT。部署状态以 CLOUD_DEPLOYMENT 为准：当前为 Cloudflare + Render + Neon，早期文档的 SQLite 描述适用于本地启动。

## 3. 接入边界

```text
实验配置 + 专家卡片版本 + 当时可见数据 + 当前持仓
                            |
                  DecisionBackend 统一接口
                  /                       \
          现有 lightweight            tradingagents
                  \                       /
              标准建议 + 专家意见 + 数据引用 + 用量
                            |
                硬性校验 → 原有人工审核
                            |
                 后续合格开盘模拟执行
                            |
                   原有账本、报告与对比
```

现有实验缺少新字段时解释为 lightweight。后端选择、上游版本、转换规则、模型、卡片和工具版本全部冻结到新实验；切换决策后端创建分支，不改写原实验。

## 4. 首个版本范围

- 美股日频，单标的，先验证 5 个决策日，再扩展至 20 个决策日；工程验收不等于统计上充分的研究。
- 使用已有导入行情，只开放行情和技术指标工具；不开放新闻、社交、财报或实时外部数据。
- 首轮使用技术分析、交易决策和风险评估相关节点；具体最小可用图在兼容性验证时确定，多空及风险讨论各至多一轮。
- 不默认启用跨日期反思记忆；实验间完全隔离。以后启用时，只读本实验且在当前日期之前已获得结果的记录。
- 支持 AI-only 和 human-review，获批后继续沿用 next-session open 成交。
- 演示/受控接口验证与真实模型调用分开标记。没有免费且已授权的模型额度时，先完成离线验证；不产生收费模型调用。

单标的首版先验证执行契约；后续多标的使用逐标的分析加统一组合构建，所有标的完成后只提交一份计划。禁止每个专家各自提交独立订单。

## 5. 后端改造任务

拟新增模块（名称可在实现时调整）：

| 模块 | 职责 |
| --- | --- |
| backend/app/agents/contracts.py | DecisionContext、DecisionResult、结构化校验 |
| backend/app/agents/lightweight.py | 搬出已有轻量编排，保持原行为 |
| backend/app/agents/tradingagents_adapter.py | 封装固定版本上游，调用与输出转换 |
| backend/app/agents/point_in_time_tools.py | 授权行情、指标、持仓与证据查询 |
| backend/app/agents/portfolio_policy.py | 显式、可版本化的评级到目标仓位转换 |
| backend/app/agents/runtime.py | 任务、预算、超时、进度与恢复 |
| backend/tests/test_agent_backends.py | 兼容性与端到端契约测试 |

统一输入包括 experiment_id、decision_id、回放时点、数据版本、只读可见历史、现金/持仓、硬约束、团队快照及剩余预算。不给适配器完整未来行情。

统一输出包含 action、targets、rationale、risks、evidence_refs、expert_opinions、usage、backend_version 和 mapping_version。由平台检查数据引用、标的范围、有限数值、非负仓位、仓位上限与总权重。

评级转换：

- 保留上游原始评级、原始输出和转换前后结果；不得通过文字猜测缺失数值。
- 首期使用确定性的、创建实验前可见的 allocation_policy_v1，将评级映射到预定风险敞口；精确映射表在第一阶段冻结并展示，不凭运行结果调参。
- 明确 Hold 保留当前持仓、Sell 在只做多范围内减至零；REVIEW 或无法解析的输出进入错误/需处理状态，不冒充 Hold 或自动成交。
- 多标的时预先定义总权重不足与超额分配规则；转换规则是实验方法的一部分。
- 本平台空 targets 表示现金配置；不得把解析失败的空字典当作合法清仓。

## 6. 数据与专家卡片

工具统一按 as_of 截断，指标只能使用截断后的历史。若需预热数据，只提供决策开始前的历史用于指标，预热期不交易且不计入评估收益；在配置中记录预热长度。

封装上游工具及可能隐式联网的标的解析、记忆、反思、基准查询，受控测试应禁止除授权模型端点以外的网络请求，确保工具不会绕过本地数据快照。

专家卡片逐步补充 backend_support、tools、required_data、prompt_version、source/license 和 role_mapping。先支持动量、趋势、风险卡片；这些卡片是我们配置的策略模板，不声称上游自带完全一致的角色。

保持一个交易主专家与若干顾问。将主专家的规则注入交易节点，顾问输出进入汇总节点；上游固定角色与我们用户卡片之间建立明确映射。缺少必要数据的卡片禁止启用。

卡片变更仍在下一决策边界生效。运行中的图必须使用创建时冻结的 team_version；当前建议保留/废弃规则继续沿用现有行为，作废后不能提交迟到输出。

## 7. 持久化、预算和任务控制

新增 agent_runs 与 agent_events 等记录，保存阶段、输入摘要、输出、模型用量、版本和失败原因。凭据只从现有加密存储读取，不放进这些记录或检查点。

首期每个实验只允许一个活动决策，平台层面限并发。初始化图、数据配置、缓存、记忆和 thread_id 必须按实验及决策隔离，不能仅以标的和日期作键。

Render 本地磁盘不作为持久记录来源；重要状态写 Neon。第一版保证决策边界恢复；进程在图内部中断时标记 interrupted，由用户重试并保留 attempt。只有 PostgreSQL 检查点适配通过测试后，才宣称节点级恢复。

长任务采用后台任务加进度查询，不让浏览器一直等待单个长请求。重启后将遗留 running 标记 interrupted，不能假装仍在运行，也不自动重放付费调用。免费后台休眠不是常驻调度保证，不添加保活服务。

使用 experiment_id + decision_id + attempt_id 与唯一提交约束，防止超时重试、重复点击、恢复与迟到响应生成重复建议或订单。账本更新仍由现有引擎事务路径完成。

所有模型节点、工具循环、结构化修复、总结和重试纳入预算。默认串行或极低并发，调用前预留费用；未知费用明确标记并停止新调用，不按零费用处理。callbacks 用于记录，但不能只依赖调用结束后的回调执行预算约束。

分别限制总调用次数、输出长度、工具轮数、讨论轮数、耗时与费用。暂停/取消后不发起新调用；在途调用可能已经计费，记录结果但不得提交失效建议。

## 10. 关键验收用例

1. 替换当前时点之后的行情，受控模型得到的输入、指标及建议保持不变。
2. 决策日收盘信号不得在同日成交；批准只入队，继续遵守后续开盘、缺失报价和最后交易日规则。
3. Hold 保留仓位；非法评级、越界权重、NaN、空输出暂停且不生成替代订单。
4. 多专家只产生一份最终方案；每位专家可观察输出与最终方案都有可追踪记录。
5. 人工批准、修改、拒绝保留原始方案；重复审核不重复成交。
6. 两个相同标的和日期、不同实验/卡片的运行，缓存、记忆、模型配置和输出互不污染。
7. 超时、失败、缺失用量、超预算及重复重试被正确记录；未调用真实模型时不标注真实模型成功。
8. 重启和暂停后，没有重复订单；遗留运行可识别；恢复不覆盖原始记录。
9. 设置、异常、检查点、报告和导出不包含 API key、会话或数据库凭据。
10. 公网验收测量峰值内存、实际耗时和冷启动，不能仅依据本机测试宣称云端可用。

## 11. 研究设计与归因

先比较相同市场数据、资金、费用和成交规则下的传统基线、现有轻量 Agent、TradingAgents 适配版。研究人工监督时分别为每种 Agent 设置 AI-only / AI+Human 两组，避免把更换框架与人工介入混为同一变量。

记录模型/提示词/框架版本、信息范围、讨论轮数与预算。为隔离即时审核效果，可在相同持仓快照下复用同一个原始建议；闭环交易中人类操作改变后续持仓时，让后续决策读取各自真实状态，并明确路径已分叉，不能强行称为完全相同建议流。

先预注册小规模实验规则，再分开开发期和最终评估期。报告收益、回撤、Sharpe、换手、交易成本、调用费用、延迟、失败率和干预次数。人工耗时需新增有效计时，服务器等待审核时间不能冒充实际工作时间。

输入按时间截断不能排除预训练模型已知历史结果；框架适配与降配也会影响论文可比性。报告命名为 TradingAgents 适配版，并披露修改，不声称原论文复现或复现其收益。
