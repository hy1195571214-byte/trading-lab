# 分钟回放与前向模拟：v2 实施约定

本次工作仅在本地进行。用户尚无 Alpaca 账户，先完成离线功能；真实行情连接需后续用账户验收。本文件定义实现约定，实际验证结果另见验收报告。

## 数据与费用边界

- 合成分钟/小时数据、加速合成行情源和确定性演示策略无需账户，不调用 LLM，不构成真实市场或 Agent 能力证据。
- Alpaca 只接固定的数据接口和 IEX 流接口，不接任何券商下单接口。基础免费 IEX 行情不是全市场成交数据。
- 数据密钥与 LLM 密钥独立，在服务端加密保存；页面只接收配置状态。后续真实模型测试需另行确定调用预算。
- 本轮不注册账户、不购买套餐、不推送代码、不更新公网部署。

## 独立版本与时间语义

- 原有日频 v1 实验沿用旧引擎，保持配置、数据快照及历史记录。
- v2 将 `market_mode`（历史/前向模拟）与 `mode`（自动/人工审核）分开。
- K 线基础周期、决策间隔、持仓上限分别配置。基础数据当前为 1 分钟或 1 小时；真实流先支持 1 分钟，不把分钟消息标成小时消息。
- 时间必须带明确时区，统一保存为 UTC。区间为 `[bar_start, bar_end)`；已结束且已可获得的数据才能用于决策。
- 历史下载以 K 线结束时间作为建模可用时间，另记实际下载时间。这是回测假设，不证明每条历史修订数据当时实际可得。
- 前向数据保留事件时间与接收时间；修订追加记录，不改写原决策快照。合成加速流使用明确的虚拟时钟。
- 持仓上限按经过的 UTC 时间解释：1d 为 24 小时。休市或缺少可用报价可能延迟退出，不暗示保证在到期瞬间成交。

## 决策与模拟成交

- 决策保留开始、完成时间与输入快照；只在决策间隔到达且有新的已完成 K 线时调用策略。
- 历史订单采用决策完成及所设延迟后，首个合格 K 线开盘价，再计算费用和滑点。
- 前向模式使用提交之后新观察到的已完成 K 线收盘价，成交时间为实验实际处理该合格报价的单调时钟，并单独保存原始接收、可用及观察时间；不能倒填过去的开盘价或处理积压前的成交时间。
- 过期行情不能触发成交。断线补采、重复消息或重复审核不能重复下单。
- 慢决策可以跳过已错过的决策边界，但必须记录跳过原因，并从持久行情事件补齐实验输入与估值。积压补录不补造前向成交；只有最新合格报价边界可触发成交。
- 达到持仓上限的退出单记录系统来源，并妥善处理冲突待执行单与过期审核建议。小幅调仓不得无限重置首次入场的到期时间。
- 到期退出按各持仓自己的到期时间和执行范围处理，保留其他尚未到期持仓；缺报价时分别等待可执行报价。
- 每笔成交记录来源 K 线起止时间，用于图表标记；决策时间与图表定位时间保留对应关系。

## 展示与评价

- 保留逐根 K 线的账户快照，回看过去时间时展示当时持仓、现金、决策和已发生的成交。
- 图表位置使用来源 K 线时间；信息是否可见使用快照的可用时钟。当前待审核操作和当前失败审计单独标示，不能伪装为历史时点已经可见的信息。
- 风险指标单独按每天最后一个净值观测汇总，采用明确披露的日收益口径；不能将分钟收益直接乘以 `sqrt(252)`。
- 采集与实验运行分别可暂停，状态分开展示。模拟演示、真实 IEX 行情、历史回放必须可区分。
- 没有真实账户连接或真实模型响应时，不宣称已完成这两类验证；短期流程测试不证明盈利或人类监督有效。
