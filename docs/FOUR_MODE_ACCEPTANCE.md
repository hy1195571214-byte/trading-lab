# 四模式验收记录

## API 独立验收

日期：2026-11-10。使用 FastAPI `TestClient` 从 HTTP 路由创建数据集、实验、执行回放、审核、调权、查询分析及导出。行情通过 CSV 导入或应用内合成分钟数据生成；模型请求在进程内替换为受控模拟响应。数据库使用各测试独立临时文件。未调用真实 LLM、券商接口或十股真实研究数据，未部署。

在后端冻结后的执行结果：`backend/tests/test_four_mode_acceptance.py` **18 项通过**（参数化后计数）。环境为 `/private/tmp/deepseek-acceptance-venv`。测试运行期间出现一条 FastAPI/Starlette 对当前 httpx 测试客户端的弃用提示，不影响本轮结果。

最终整合回归在清除 API、数据库和认证环境变量后执行全部 `backend/tests` 与 `backend/app/engine_tests`，主 agent 独立复跑结果为 **164 项通过，1 条上述弃用提示**，耗时 28.38 秒。其中开源量化适配器专项测试为 **9 项通过**。

覆盖的主要行为：

- 四种模式分别通过日线及历史分钟 HTTP 路径创建并产生真实决策；量化模式不调用模型。`bt_buy_hold` 初始等权后保持持股；`bt_sma50` 在第 50 根日线计算目标，第 51 根开盘执行，早期预热无持仓。
- 分别捕获三个分析模块的实际输入，检查证据类型隔离、无其他分析结果和共享评分；未知或跨标的引用导致失败，不生成决策或订单。
- 一个标的的正权重新闻模块缺失时，经过下一日价格跳变仍保持原股数，同时卖出另一标的并买入第三个标的；人工修改为完整目标后，原保留标的能正常卖出。
- 权重格式、理由、仅人机模式可调权、待生效请求不可覆盖；待审核期间旧决策与历史分析不变，下一新决策采用新版本；同一时点失败重试仍用原版本。
- 零调用额度及零预算阻止模型调用和订单；旧实验路径仍可决策；分析接口和 JSON、CSV 导出分别记录两类介入及计数，调权事件包含请求和生效时点。

边界：这是本机 HTTP 应用和模拟模型的合成数据验收。真实模型质量、投资收益、外部数据、真实券商和实时采集器需要独立验收。历史分钟测试验证下一可成交开盘规则，真实市场流动性与成交仍需另行评估。
